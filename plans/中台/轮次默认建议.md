## R3. 内容包如何传到中台

### 默认路径

| 阶段 | 方式 | 说明 |
| --- | --- | --- |
| **试点** | **人工/脚本导出 zip**，运营或脚本上传到中台导入接口或对象存储投递区 | 最快验证契约，不绑部署形态 |
| **稳态** | **Conductor 侧主动推送**：`POST /content-packages`（元数据）+ 媒体按 R4（同 zip 或先 URL 后 JSON） | 中台不轮询本机 `output/` |

不推荐把「中台扫 Conductor 磁盘」当通用方案（仅内网同盘时可用，见草案 §11 P1）。

### 接口最小语义（稳态）

- `POST /content-packages`：创建或按 `package_id` 幂等写入草稿
- `PUT /content-packages/{package_id}`：同 package 内容更新（新 batch / 补媒体）
- `GET /content-packages/{package_id}`：查询入库状态与缺失媒体
- 鉴权：中台颁发的 API Key / OAuth；Conductor 不持有平台店铺 token

### 幂等与版本

- 主键：`package_id`（建议稳定：`{listing_id}@{platform}-{market}@{batch}`，多平台覆盖包可用 `listing_id@multi@{batch}`）
- 同一 `package_id` 重复提交：中台覆盖更新内容与媒体清单，保留历史版本可选
- Listing 目录 `-v2` 对应新的 `batch` / 新 `package_id`，不静默覆盖中台已推送成功的刊登记录

### 与媒体通道

- 试点：一个 zip 同时含 JSON + 图（视频可另附）
- 稳态：仅当 `content_status=ready`（文案、必填媒体与门禁均通过）才 `POST`/`PUT` 到中台；`partial`/`blocked` 不发送。

### 中台有无现成 schema

**默认假设：中台暂无现成导入 schema，或以 Conductor 的 content-package 为准做适配层。**  
若中台已有 schema，由中台做映射表，Conductor **不**为迁就中台字段改内容生产规则；最多增加导出转换脚本（仍属对接层，不进 Agent 提示词）。

## R5. 刊登状态回写

### 默认：回写以中台为主，Conductor 可选落盘摘要

| 信息 | 存放位置 |
| --- | --- |
| 刊登成功/失败、平台 item_id、媒体平台 URL、错误码 | **中台权威** |
| 可选：最近一次推送结果摘要 | Conductor `output/.../上架/中台推送结果.md` 或 JSON sidecar（人工查阅用） |

**不要求**中台写回改 Agent 规则或覆盖 `文案/`、`图片/` 源文件。

### 回写字段建议（中台 → 可选回 Conductor）

```json
{
  "package_id": "...",
  "platform": "Temu",
  "market": "US",
  "push_status": "success | failed | pending",
  "platform_item_id": "...",
  "platform_media_ids": [{ "media_id": "image-custom_main-01", "platform_media_id": "..." }],
  "error_code": null,
  "error_message": null,
  "pushed_at": "..."
}
```

### 失败处理

- 内容问题（缺图、待确认事实）：改 Conductor 内容包后重新提交新 batch 或更新同一 package
- 接口/账号/限流：只在中台重试，不回流 Conductor 重生成内容

## R6. 首个试点范围

### 默认试点

- **平台-市场：Temu-US**
- **样本商品：马克杯 SKU（如 `MUG0110RD`）**，已有 CSV、主白底图与 Temu 定制类 8 图规则
- **范围**：文案 + 图片 content-package；ready 门禁为文案与约定套图齐，视频不强制。未 ready 的包不发中台。
- **传输**：P0 zip 人工/脚本导入中台
- **成功标准**：中台能入库、按 Temu 覆盖合并、完成一次沙箱或测试店铺提交（或至少组装出可检查的 API 报文）

### 明确不进首期

- 多平台同包覆盖、自动对象存储、状态自动回写 Conductor、写入 AGENTS 强制规则

## R7. 多平台与推荐平台

1. **默认单平台一包**：上品文案在顶层 `copywriting`；`platform_overrides` 默认只含图集/视频/备注，不重复文案。落盘仍用 `output/{平台}-{市场}/`。
2. **推荐平台 ≠ 必推平台**：`metadata.recommended_platforms[]` 只标记建议可推的平台；**是否推送到其他平台由中台决定**，Conductor 不强制预生成多平台文案。
3. **中台跨平台推送**：可基于本包事实 + copywriting + 媒体自行映射/改写后提交；缺某平台专用文案时由中台处理，不回堵 Conductor。
4. **多平台同包（可选例外）**：仅当用户明确要求同一包内带多套平台文案时，才增加 `platform_overrides[].copywriting`。
5. **媒体复用**：同一 `media_id` 可被中台用于多平台上传。
6. **平台内容规则仍在 Conductor（对本包 content_platform）**；**平台接口映射只在中台**。

### `platform_overrides` 覆盖粒度（已收窄默认）

- **默认**：只认 `image_set` / `video_set` / `content_notes`。
- **例外**：用户明确要求多套平台文案时，可认 `copywriting`。
- 其余未知字段忽略但不报错（前向兼容）。

## 其他默认补齐

### 完整生产报告对中台是否可见

**默认：不对中台必传。** 人对人归档；机对机只认 content-package。中台若要审计，可另开「附件可选」开关，不进刊登主路径。

### 合并冲突与人工确认

- `needs_human_confirmation` 非空 → 中台可入库，默认不可推送，直到中台侧人工放行或 Conductor 更新包去掉该项
- Conductor 与中台对同一 SKU 的「建议类目」不一致时：以中台映射表为准选类目 ID，Conductor 文本仅作参考

### 安全

- zip / 对象存储链接需访问控制；签名 URL 设过期时间
- Conductor 不落盘、不传输平台店铺密钥
- 日志脱敏：不打印完整授权头

### 可观测性

每次导入记录：`package_id`、`schema_version`、文件数、校验和失败列表、耗时。便于联调对账。

### 错误码建议（中台返回 Conductor）

| 码 | 含义 |
| --- | --- |
| `PACKAGE_ACCEPTED` | 已保存（应为 ready 包） |
| `PACKAGE_REJECTED_NOT_READY` | 拒收：content_status 非 ready 或门禁未过 |
| `MEDIA_MISSING` | 引用的 media_id 无文件 |
| `CHECKSUM_MISMATCH` | sha256 不符 |
| `SCHEMA_INVALID` | JSON 不符合契约 |
| `PUSH_FAILED_CONTENT` | 推送因内容/映射失败 |
| `PUSH_FAILED_PLATFORM` | 推送因平台 API/账号失败 |
