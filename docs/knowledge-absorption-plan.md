# 外部知识吸收清单

本文档用于记录外部知识文档如何吸收到 Conductor。默认不直接改变正式 Agent 规则；只有用户明确要求“写入规则”或“同步到正式 Markdown”时，才修改 `AGENTS.md`、`agents/`、`platforms/`、`templates/` 或 `workflows/`。

## 来源文档

| 文档 | 当前定位 | 适合用途 |
| --- | --- | --- |
| `creativity-models.md` | 创意模型参考 | 文案框架、广告短文案、图片脚本、视频故事选择 |
| `amazon.cosmo.md` | Amazon 语义意图参考 | Amazon 标题、要点描述、关键词、后台词、A+、图片脚本 |
| `amazon.listing.optimization.expert.md` | Amazon Listing 优化参考 | Amazon 专用执行流程、Rufus 问题预判、视觉脚本和 Q&A |

## 吸收原则

- 现有项目 Markdown 是最高执行依据；外部文档不能自动覆盖当前规则。
- 官方平台规则、平台后台要求和项目已确认规则优先于运营经验或方法论。
- 外部文档中的策略只能作为生成质量增强，不得用于编造未确认事实、认证、材质、功效、销量、排名或授权。
- 冲突内容必须先列为“待确认”，不得直接进入正式规则。
- 可执行规则要短、清楚、可验收；长篇解释保留为参考，不写入核心 Agent 指令。

## 冲突和暂不吸收项

| 内容 | 冲突点 | 处理方式 |
| --- | --- | --- |
| Amazon bullet “必须六点描述” | 当前项目规则是 Amazon 按 5 条 bullet points 输出 | 暂不吸收；除非用户明确确认 Amazon 改为 6 条 |
| 外部文档中的启动话术 | 会破坏 Conductor 当前“你好/菜单/数字选择”启动流程 | 不吸收 |
| “专家系统已就绪”等角色话术 | 与当前指挥家流程编排定位冲突 | 不吸收 |
| 未注明来源的算法判断或平台实时规则 | 可能过期或不可验证 | 只作为策略参考，不作为硬规则 |

## 推荐落地顺序

1. 已新增通用语义与创意规则，适用于所有平台，但不覆盖平台专用规则。
2. 已补充 Amazon 专用增强点，只影响 Amazon，不影响 Temu、Shopify、Etsy 和 TikTok Shop。
3. 已补充 QA 验收项，检查输出是否覆盖语义意图、创意策略来源、证据锚点、买家问题预判和图片信息层级。

## 已吸收细节

- 已把 COSMO 类意图拆成跨平台语义意图映射表，并补充事实等级，区分已确认事实、合理推测、市场建议和待确认项。
- 已补充语义到产物映射：标题、要点描述、长描述、搜索关键词、后台关键词、图片脚本和视频脚本分别承载不同意图。
- 已把创意模型拆成平台推荐组合：Amazon 用 FAB + 语义意图映射，Temu 用 FAB + AIDA，Shopify 用 4P + PAS，Etsy 用 SSS + FAB，TikTok Shop 用 AIDA + SSS。
- 已补充买家问题预判和承载位置：规格图、要点描述、FAQ、Q&A、包装图、视频演示等分别回答不同问题。
- 已补充视觉脚本生成顺序：先平台必备图型，再分配语义意图，避免多张图重复表达同一卖点。
- 已补充销售单位/组合关系、变体与定制边界、搜索/任务意图、决策阻力和证据锚点，避免通用语义只覆盖营销场景而忽略真实上架关系。
- 已区分“是否展示创意菜单”和“是否形成创意策略”：直接输出、强规格商品或用户已给方向时可以免交互，但正式产出仍需记录默认策略或沿用方向。
- 已限制图片可见事实、高风险声明和 Before/After 画面的证据边界，并将创意模型名称保留在卖家侧规划中。
- 已补充 Amazon 专用标题、5 条要点描述、关键词、Q&A、A+ 和图片脚本规则，并明确不吸收外部文档中的 6 条 bullet 要求。

## 吸收后的验收重点

- Amazon 的完整生产报告是否仍严格使用 16 章标准模板，日常聊天是否只展示本轮相关结果。
- 卖家侧栏目是否仍使用中文，买家可见文案是否使用目标市场语言。
- Amazon 要点描述是否按当前项目约定输出 5 条，除非用户确认改为 6 条。
- 标题、关键词和图片脚本是否覆盖功能、场景、受众、时间、搭配和购买动机。
- 所有事实是否来自用户资料、商品资料库、可访问平台页面或明确标注为待确认。
