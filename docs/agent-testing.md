# Agent 测试与验收

本文件用于验证 Conductor 的用户流程是否同时做到“少输入、少重复、可继续执行”和“事实、平台规则、交付质量不降级”。普通使用从 `hello` 或“你好”开始，不需要手写模板名称。

## 验收原则

- 只向用户索取当前任务无法可靠获得的最低必要信息。
- 已在会话、商品资料库或附件中提供的信息不得重复询问。
- 减少输入不能以编造事实、跳过确认商品档案、降低平台规格或省略质量验收为代价。
- 用户选择菜单或下一步动作即视为同意执行该范围内的工作；仅在扩大范围、覆盖已有文件或产生外部影响时再次确认。
- 给卖家看的内容使用中文；可直接投放给买家的文案使用目标市场语言。

## 规则一致性自动检查

该检查供项目开发和规则维护使用，不参与日常商品生产。当 Agent、工作流、模板、平台规则、README 或商品资料库发生修改时，用它快速发现已经确定的约定是否被意外破坏。

在仓库根目录执行：

```bash
npm test
```

当前自动检查覆盖：

- 核心 Agent 没有重新设置一组适用于所有任务的统一必填字段。
- Listing 定制流程区分商品定制能力与卖家定制服务，并覆盖普通成品、DIY 空白基底、定制必选、定制可选、待确认和输入冲突分支。
- 启动词、动态输入和 SKU 标准化规则仍然存在。
- 多个 SKU 始终组成一个 listing，默认数量和重复 SKU 合并规则未被误改。
- 用户选择动作后不被重复确认，同时保留覆盖文件保护。
- 创意方向选择流程文档存在，并被主规则、启动向导和 README 引用。
- 聊天简版模板包含状态、相关产出、风险、文件和下一步动作，完整生产报告仍包含 16 个章节。
- Temu 定制类默认 9 张图的图型保持完整，尺寸规格图和尺寸对比图分别存在。
- `product-catalog.csv` 和 `product-attributes.csv` 存在，表头、列数、SKU、数字、日期、允许值和属性关联通过校验；商品主图由 SPU/SKU 自动定位并检查缺失与扩展名冲突。
- Markdown 中引用的本地规则和文档链接能够找到目标文件。

也可以单独运行定制流程检查：

```bash
node scripts/check-customization-flow.mjs
```

该检查确认普通 5 件装和 DIY 空白基底不会生成卖家定制操作图，定制必选和可选会进入正确分支，服务待确认时只显示“不提供 / 必须 / 可选”三个同级选项。

它不检查：

- AI 是否严格按照规则完成了一次真实对话。
- 文案是否有足够的市场竞争力。
- 图片是否自然、商品是否变形或文字是否正确。
- 视频是否真正具有动态画面、情绪口播和同步字幕。
- 平台实时规则、热销数据、评论和供应商链接是否发生变化。

因此，`npm test` 通过只表示“仓库内已确定规则没有发现结构性冲突”，不表示完整业务流程已经通过。下面的对话用例和产物验收用于检查实际执行质量。

如果检查失败，终端会显示具体原因。应修正规则或引用关系后重新运行，不应为了让测试通过而删除仍然有效的业务约束。

## 一、入口与任务分流

分别输入：

```text
hello
```

```text
 HELLO
```

```text
你好
```

通过标准：

- 只显示纯数字启动菜单，不输出 16 章生产模板。
- 忽略英文大小写和入口词首尾空格。
- 用户输入数字后按最近一次菜单解释，不要求用户复述任务。
- 选择找品、竞品分析、合规检查、QA 或查看产物时，不统一索取商品名称和商品图。

## 二、最低必要输入

从菜单选择 `1`、`2`、`8`、`10`，逐项检查：

- 文案任务只要求商品名称或 SKU、目标平台、目标市场；商品图为建议提供。
- 图片、视频或完整资产任务只有在商品资料库缺少可靠外观依据时，才要求图片、可靠商品链接或充分外观资料之一。
- QA 只索取待检查内容、链接、文件或产物路径。
- 输入模板带有真实示例值，可直接复制修改；不得先让用户填写核心功能、卖点、购买动机、场景、人群或完整产品档案。
- 内容生产任务的最低输入提示必须预告“先确认卖家定制服务（需要时），再完成研究并确定创意方向，然后生成并回传完整商品示例，确认后正式生成产物”，不得写成“确认商品资料后直接输出标题、图片或视频”。

### 已上架数据复盘门禁

从启动菜单选择 `11`，逐项检查：

- 最小输入模板必须包含实际商品详情链接、复盘时间范围和运营数据来源；产品名称只能标为选填或辅助核对。
- 只提供商品名称、SKU 或运营数据时，只提示补充有效 Listing 身份，不分析原因，不生成复盘报告，不返回保存路径，也不调用输出版本分配器。
- 链接必须实际打开并验证最终地址和页面类型；搜索/列表页、平台首页、登录页、验证码/风控页、下架页和错误页不得当作有效商品详情页。
- 平台没有公开详情页时，卖家后台 Listing 链接可以作为入口；工具无法读取后台页面时，必须取得平台商品 ID 和当前页面截图。
- 链接用于核对当前标题、图片、价格、评价摘要和页面状态，不能替代卖家后台的曝光、点击、加购、转化、订单、退款或广告数据。
- 复盘时间范围必须与运营数据和页面变更时间对应；口径不一致时标记不可归因，不得强行给出确定结论。
- 无匹配 SKU 时，输出目录使用已验证的 `平台商品-{平台商品ID}`；不得按商品名称创建 `未建档-{商品名}` 目录。
- 链接与产品名称、SKU 或既有档案明显冲突时暂停，让用户确认实际复盘对象，不得按名称覆盖链接所指 Listing。

## 三、商品资料库与 SKU

### 单 SKU 标准化

输入带不同大小写和首尾空格的已存在 SKU：

```text
商品或SKU：  mug-rd-11oz
目标平台：Temu
目标市场：美国
```

通过标准：忽略大小写和首尾空格，命中后返回商品主表中的标准 SKU，并自动合并主表、扩展属性和对应图库；已经读取的资料不再询问。

### 多 SKU 组合

```text
商品或SKU：sku-a * 2, SKU-A × 1, sku-b
目标平台：Temu
目标市场：美国
```

通过标准：始终按一个组合 listing 处理；相同 SKU 合并为 `SKU-A × 3`，未写数量的 `sku-b` 默认为 1。不得询问“分别生成还是组合销售”。

### 未匹配商品

```text
商品或SKU：abc
目标平台：Temu
目标市场：美国
```

通过标准：依次尝试 SKU 精确匹配、商品名称精确匹配和相似商品参考；仍未匹配时按新商品处理。相似商品只能帮助选择字段和提出建议，不能把其材质、尺寸、认证或功能当作当前商品事实。

### 部分匹配与冲突

- 组合中只有部分 SKU 命中时，保留已命中资料，只追问未匹配组件的最低必要信息。
- 商品主表存在忽略大小写和首尾空格后相同的两个 SKU 时，停止匹配并明确报告资料冲突，不得随机选择。

## 四、自动商品示例

收到最低必要输入后，通过标准：

- 自动生成一份已填写、可复制、可修改、可重新生成的商品资料示例。
- 包含核心功能、希望突出卖点、主要购买动机、定制示例、销售单位与包含内容、目标平台热销参考链接 2-3 个，以及平台和类目必需属性。
- 建议基于商品、可访问同类商品和评论痛点；未获取数据时明确写“未获取”，不得编造。
- 节日必须属于目标市场、尚未过去且扣除生产、物流和营销准备后仍来得及。
- 高风险或自身未证实的事实写“待确认”，不进入买家文案。
- 普货的定制示例写“不适用”。定制商品的目标市场标题可动态加入定制意图，但不改写资料库中的基础商品名称。
- 操作说明在代码块外，代码块内只有商品资料本体。
- 用户回复“重新生成示例”时保留已提供事实，只更换有依据的营销建议。
- 完整商品资料示例外固定提供“重新选择创意”和“重新生成创意”两个入口，不提供“改选创意 3”等直接改选语法。
- 回复“重新选择创意”时原样重新展示上一轮候选菜单；回复“重新生成创意”时废弃上一批候选，重新研究并生成与上一轮语义去重的新菜单。
- 触发任一创意调整入口后暂停商品示例确认与正式生产，完成新的数字选择后重新生成完整商品资料示例。
- 用户回传示例前不进入正式生产；回传后不重复要求确认同一份资料。

## 五、正式产出

用户复制、修改并回传商品示例后，通过标准：

- 单项任务的聊天结果包含 `## 1. 本轮状态` 至 `## 5. 下一步动作`，只展示本轮相关产出，不显示无关章节。
- 正式执行同时生成完整生产报告，文件名固定为 `上架/完整生产报告.md`；再次执行时整批写入 `{Listing标识}-v2/`、`-v3/` 目录，不给报告文件名添加版本后缀。
- 保存的完整报告包含 `## 1. 输入摘要` 至 `## 16. 下一步执行清单`；未执行章节写“本轮未执行”，缺失事实写“未提供”或“待确认”。
- 选择完整流程、完整上架包、上架前 QA/完整验收，或明确要求完整报告时，聊天直接展开完整 16 章。
- 平台策略包含通用语义意图摘要、创意模型选择和买家问题预判，但不得把市场建议写成已确认事实。
- 文案任务的完整报告包含“标题关键词证据”表，主要关键词记录类型、数据来源、查询入口、抓取日期、可见信号、商品事实状态、采用结果和标题位置。
- 标题数据优先级为自身商品事实、目标平台数据、目标市场搜索、趋势工具、内容平台、其他电商平台。Google Trends 不得被描述成目标平台搜索量，Instagram/TikTok/YouTube 场景词不得被描述成目标平台关键词证据。
- 目标平台无法访问时必须写“未获取”并降低结论可信度，不得用 Amazon、Google 或社媒数据冒充 Temu 数据。
- Amazon、Temu、Shopify、Etsy、TikTok Shop、eBay、AliExpress 和 Walmart 必须分别使用各自的平台标题结构和站内数据优先级；多平台任务分别研究、组词和输出。
- 产品定位包含创意策略记录，说明是否展示创意方向菜单、创意策略来源、采用的创意方向、证据锚点、本轮所需内容执行主线和风险边界。
- 要点描述按目标平台改写，不得把 Amazon 5 条 bullet 结构套用到 Temu、Shopify、Etsy、TikTok Shop 等其他平台。
- Temu 商品描述按空行拆分段落，每段最多 `500` 个字符；字母、数字、空格和标点符号全部计数。每段应记录字符数，任一段超过 `500` 时不得通过文案或上架 QA。
- 保存 Temu 文案后运行 `node scripts/temu-description-limit.mjs <文案 Markdown 路径>`；自动测试必须证明 `500` 个字符通过、`501` 个字符失败、多个段落分别计数。
- 下一步清单不能为空，并只展示 1-5 个本轮任务范围内的动作；只有 1 个合理动作时不得用扩展任务凑数。
- 启动菜单 2 完成文案与图片后，下一步不得包含上架前 QA、上架包、供应链、利润、视频、合规或测试；`node scripts/next-action-scope.mjs 2 <动作ID...>` 必须通过。
- 菜单 1-12 必须逐一拒绝所有其他范围的动作；组合菜单只允许各已选范围的并集。回归测试必须遍历全部稳定动作 ID，不能只测试菜单 2。
- 用户选择一个动作后直接执行，不再次询问是否执行；覆盖已有文件、扩大范围或产生外部影响除外。
- 所有产物保存到声明的输出路径，不静默覆盖已有文件。
- 写入前把基础 Listing 目录传给 `node scripts/output-versioning.mjs`；连续执行两次时，第二次所有产物统一进入 `{Listing标识}-v2/`，目录内文件名保持不变，且首次目录中的产物内容保持不变。存在更高或不完整的历史版本目录时，整批跳到当前最大目录版本的下一个版本。
- 只创建本轮实际产物需要的子目录；未执行供应链、利润、合规、测试、竞品或视频时，对应目录不得存在。`node scripts/check-output-layout.mjs` 必须通过。
- 输出根目录使用 `output/{平台}-{市场}/{Listing标识}[-vN]/`；单 SKU 使用标准 SKU，多 SKU 使用包含数量的稳定组合标识，生产版本只添加到 Listing 目录末尾，商品名称和类目不得形成额外目录层级。

## 五A、创意方向选择

选择包含文案、图片或视频的任务，在生成商品示例前，通过标准：

- 存在至少两个可执行方向并需要用户收敛时，只输出 3-5 个纯数字创意方向菜单，不输出 16 章正式模板。
- 每个方向包含当前商品专属的创意主题或钩子、适合人群、购买动机、证据锚点、执行差异、推荐理由和风险边界，不能只显示通用类型名称。
- 用户回复 `1`、`2` 等数字后，不再追问创意字段，直接生成可执行创意方案和与之对应的完整商品示例。
- 用户回复多个创意编号时，不静默采用第一个，也不直接混合多个主题；提示一次选择一个主方向。
- 用户输入 `0` 时，系统自动选择并说明选择依据，然后生成完整商品示例；旧对话中的“自动选择”仍能兼容。
- `0` 只在最近一次展示的是创意方向菜单时表示自动选择，不得改变启动菜单或下一步动作菜单的编号含义。
- 用户明确要求直接输出或跳过菜单时，不出现创意菜单，但完整报告第 6 节仍记录系统默认策略；用户已给方向时记录“沿用用户方向”。
- 本轮只做供应链、利润、合规、QA、保存或查看产物时，不出现创意菜单，完整报告第 6 节写“不适用”。
- 只生成本轮请求的内容执行主线；例如仅文案任务的图片主线和视频主线写“本轮未执行”。
- 创意方向不得把未确认功能、材质、认证、授权、销量、尺寸或效果写成商品事实。
- AI 生成细节图、认证标志、评价星级或信任徽章不得被当作证据；缺少真实依据的细节必须标记“待补实拍”。
- 用户回传商品示例后必须检查创意是否仍成立；局部事实补充沿用原创意，商品身份、外观、平台、市场、卖家定制服务、销售组合、核心功能、目标人群或核心场景发生实质变化时重新选择创意并更新示例。

## 六、Temu 定制类图片

选择 Temu 定制类商品并执行完整套图，通过标准：

1. 最终定制主图。
2. 到手内容/包装图。
3. 定制操作示意图。
4. 尺寸规格图。
5. 尺寸对比图。
6. 细节放大图。
7. 日常使用场景图。
8. 情绪/礼赠场景图。
9. 卖点集合图。

补充检查：

- 9 张图均为独立文件，不用拼图、九宫格或缩略图预览代替。
- 主图展示实际售卖数量；套装、多件装不能画成单件。
- 定制内容先自然贴合商品，再用于主图、包装图和场景图。
- 尺寸图同时显示 `cm` 和 `inch`。
- 尺寸对比图与尺寸规格图为两个独立文件，参考物尺寸可靠、比例真实，并标注 `Size Reference` 和条件需要的 `Not Included`。
- 场景、包装、规格和卖点图含基于已确认事实的简短目标市场语言文案。
- `YOUR NAME`、`YOUR TEXT`、`CUSTOM PHOTO` 不作为最终商品图案。
- 只有多种定制方式会直接影响购买选择时，才可用定制效果示例图替换第 8 张，并记录理由。
- 少于 9 个独立文件或缺少必备图型时，状态必须是“未完成”，并提供“继续生成缺失图片”。

## 七、商品视频

通过标准：

- 根据平台、品类、商品外观和卖点自动选择合适广告故事，不依赖实拍视频。
- 有真实动态动作和镜头连续性，不用静态图片轮播、推拉或转场冒充视频。
- 同时包含可听的目标市场语言口播和烧录字幕，缺一项即“未完成”。
- 口播有与故事匹配的情绪、停顿、重音和语速变化，不机械照读字幕或参数。
- 字幕为纯文字叠加，不使用背景条、气泡、卡片或半透明底。
- 音乐、口播和音效可商用或由工具原创。
- Temu 成片仅使用 `1:1`、`3:4` 或 `16:9`，不超过 60 秒和 100 MB，无黑边、无水印、非 PPT，并突出 1-3 个已确认卖点。

## 八、市场、评论与供应链

通过标准：

- 根据目标国家选择数据源并先生成本地语言关键词；非美国市场不只使用英文或美国数据下结论。
- 无法读取的销量、评论、排名、趋势或联系方式明确写“未获取”“需登录”或“受访问限制”。
- 目标平台热销参考默认提供 2-3 个已验证链接；相近平台只能作为补充，不能替代目标平台结论。
- 中国供应链优先顺序为 1688、国内专业货源平台、可验证中国供应商来源，再以 Alibaba 国际站补充。
- 交付链接必须实际打开并识别页面类型。有效报价必须包含平台、店铺、网址、价格区间、MOQ、抓取日期和获取状态。
- 用户只负责完成登录或验证码；Agent 继续搜索、筛选、打开页面和提取可见资料。

## 九、失败判定

以下任一情况应判定测试失败并修正规则：

- 把可从资料库读取的信息再次交给用户填写。
- 为了少问而猜测尺寸、材质、认证、功能、销量、评论或授权状态。
- 多 SKU 被当作多个独立任务，或未同步影响标题、图片、包装清单和数量。
- 商品示例未确认就进入正式生产。
- 需要创意方向时未出现数字菜单，或选完数字后仍要求用户手写创意内容。
- 卖家侧出现大段英文，或买家侧最终文案没有使用目标市场语言。
- 用户已选择动作后仍被重复确认。
- 图片或视频未达到平台完成标准却标记为“已完成”。
