# 商品白底图库

按以下结构存放每个 SKU 的原始商品图片：

```text
{SPU}/{SKU}/main.png
```

每个 SKU 至少需要一张 `main` 主白底图。其他图片按实际情况补充：

```text
back.png
left.png
right.png
top.png
detail-01.png
detail-02.png
```

## 文件说明

| 文件名 | 是否必需 | 内容要求 | 主要用途 |
| --- | --- | --- | --- |
| `main.png` | 必需 | 商品正面或最能代表商品的标准白底图；完整展示实际售卖数量、颜色和款式 | SKU 识别、外观基准、主图和后续视觉生成依据 |
| `back.png` | 选填 | 商品背面白底图；保持与 `main` 相同 SKU、数量和拍摄尺度 | 识别背部结构、接口、图案或背面定制区域 |
| `left.png` | 选填 | 从商品正面观察时的左侧视图 | 识别左侧结构、厚度、把手、开口或配件位置 |
| `right.png` | 选填 | 从商品正面观察时的右侧视图 | 识别右侧结构、厚度、把手、开口或配件位置 |
| `top.png` | 选填 | 从商品正上方拍摄的俯视图 | 识别顶部、内部、开口、杯口、盖子或容器结构 |
| `detail-01.png` | 选填 | 第一处最重要细节的清晰近景 | 识别材质纹理、印刷区域、连接结构、接口或工艺细节 |
| `detail-02.png` | 选填 | 第二处不同细节的清晰近景，不与 `detail-01` 重复 | 补充另一处结构、材质、工艺、标签或配件细节 |

## 角度定义

- `left` 和 `right` 以 `main` 中商品正面朝向为基准，不以拍摄者站位或商品自身使用方向为基准。
- 各角度图必须属于同一个 SKU，颜色、尺寸、结构、定制内容、配件和销售数量保持一致。
- 图片应尽量使用纯白或干净浅色背景，商品主体完整，不被裁切，不使用拼图、水印或无关文字。
- 角度图主要用于建立商品外观事实，不要求预先加入卖点文案、场景人物或装饰道具。

## 细节图命名

需要更多细节图时按顺序增加：

```text
detail-03.png
detail-04.png
```

每张细节图应展示不同信息。不要把同一张图片复制后改名，也不要只用数字变焦制造多个重复细节文件。

## 可选扩展

如果同一角度确实需要多个参考文件，可以使用：

```text
main-02.png
back-02.png
top-02.png
```

系统始终优先使用无编号的 `main.png` 作为主白底图。扩展文件只作为补充，不替代必需的 `main`。

支持的扩展名为 `png`、`jpg`、`jpeg`、`webp`。同一角色不得同时存在多个扩展名，例如不能同时放置 `main.png` 和 `main.jpg`，否则系统必须标记文件冲突。

## 缺失处理

- 缺少 `main`：文案任务可以继续，但必须标记“未加载主白底图”；图片、视频和完整上架任务需要用户补图或提供其他可靠外观依据。
- 缺少其他角度图：不阻塞任务，系统只使用现有图片，不得推断看不见的背面、侧面、顶部或结构细节。
- 不得借用同一 SPU 下其他 SKU 的图片补齐缺失角度。

系统根据 `product-catalog.csv` 中的 SPU 和 SKU 自动定位目录，不在 CSV 中逐张维护图片路径。
