# 商品资料库

本目录保存可重复使用的商品事实和原始商品图片，避免每次任务重复填写尺寸、材质、颜色、商品特点和包装信息。

## 文件结构

```text
data/
├── product-catalog.xlsx
└── products/
    └── {SPU}/
        └── {SKU}/
            ├── main.png
            ├── back.png
            ├── left.png
            ├── right.png
            ├── top.png
            └── detail-01.png
```

## 使用方法

1. 在 `product-catalog.xlsx` 的“商品主表”增加或维护通用商品记录。
2. 商品有品类专属参数时，在“扩展属性”增加对应属性行。
3. 按 `data/products/{SPU}/{SKU}/` 建立图片目录。
4. 每个 SKU 至少提供一张 `main` 主白底图。
5. 用户在任务中提供一个或多个 SKU 及数量后，系统合并工作簿中的商品主表和扩展属性，再加载各自图片目录并在本轮识别组合形态。

工作簿只保存已经确认、可直接使用的商品资料。

## 工作簿结构

“商品主表”只保存跨品类通用字段，例如：

- SPU、SKU、名称、类目和产品类型。
- 单个 SKU 固定包含的商品或配件。
- 通用长宽高、重量、材质、颜色、型号和规格。
- 已确认功能、商品特点、适用对象和护理说明。
- 定制、包装和认证信息。

“扩展属性”使用“一行一个属性”的方式保存品类专属参数，例如：

- 马克杯：容量、杯口直径、底部直径。
- 服装：胸围、衣长、面料克重、版型、尺码范围。
- 电子配件：接口组合、传输速率、供电功率、兼容系统。
- 宠物用品：适用宠物、容量、承重、适用体型。
- 家具：座高、承重、安装方式、展开尺寸。

这样新增品类时只需增加属性行，不需要持续扩充主表列数。

## 扩展属性填写

扩展属性表字段包括：

- `属性组`：例如容量与尺寸、服装规格、接口、兼容性。
- `属性名称`：例如杯口直径、面料克重、接口组合。
- `属性值`：保存实际数值或文本。
- `单位`：例如 cm、oz、g/m²、W。
- `值类型`：数字、文本、布尔值或列表。
- `是否平台必需`、`适用平台`：记录平台或类目要求。

“选项字典”维护产品类型、认证状态、值类型和目标平台等下拉值。“填写说明”维护字段、单位、多选和图片目录规则。

扩展属性表也只填写已经确认的属性。未知或待确认属性不写入正式工作簿，由具体任务标记为“待确认”。

扩展属性表不重复保存 SPU，因为 SKU 全局唯一。扩展属性的 SKU 必须通过下拉菜单从“商品主表”选择，不允许手工输入主表中不存在的 SKU。同一 SKU 可以有任意数量的扩展属性，系统读取时仅按 SKU 合并到商品主记录中。

## 匹配优先级

```text
当前对话中用户明确修改
> 工作簿“商品主表”中的 SKU 精确匹配记录
> 工作簿中的 SPU/商品名称唯一匹配记录
> 已确认供应商资料
> 商品图片可见事实
> 同类商品和评论形成的市场建议
```

- SKU 精确匹配优先。
- 同一个名称匹配到多个 SKU 时，必须让用户选择。
- 不得借用同一 SPU 下其他 SKU 的图片。
- 工作簿的空值不得由竞品资料自动覆盖。

## 原子 SKU 与临时组合

“商品主表”的每一行只表示一个可独立识别的原子 SKU，不保存 listing 层面的“销售单位/组合形态”“销售数量”或“同款/混色/混款”。需要组合销售时，在任务中临时输入 SKU 和数量，例如：

```text
SKU组合：
- MUG-RD-11OZ × 2
- GIFT-BOX-001 × 1
```

系统按本轮输入自动识别：同一 SKU 多件为多件装；同一 SPU 的不同颜色或款式通常为混色/混款；不同组件 SKU 通常为套装。识别结果必须先展示给用户确认，并用于标题、包装清单、图片数量、成本和平台属性。本轮组合默认不回写商品资料库；只有用户明确要求建立新的套装 SKU 时才新增记录。

## 多值字段

同一个字段需要填写多个值时，使用半角竖线 `|` 分隔，例如：

```text
白色杯身|红色内胆|红色把手
文本|图片
```

## 数字和单位

- 长度尺寸统一以 `cm` 数值保存，生成美国市场示例时自动换算为 `inch`。
- 重量统一以 `g` 数值保存。
- 长度、重量和包装尺寸均设置为强制数字校验；输入文字、单位或其他非数字内容会被阻止，未知时留空。
- 容量等品类属性写入“扩展属性”，可分别保存 `oz` 和 `ml` 两行，或保存已确认的主单位并在生成时换算。
- 无法确认的数字留空，不要在数字字段写描述性文字。

供应链研究按任务实时执行，候选供应商和报价保存到本次任务的 `output/`。

## 图片命名

- `main`：必需，主白底图。
- `back`、`left`、`right`、`top`：选填角度图。
- `detail-01`、`detail-02`：选填细节图。
- 支持 `png`、`jpg`、`jpeg`、`webp`。
- 同一角色不得同时存在多个扩展名文件，例如不能同时放置 `main.png` 和 `main.jpg`。
- 无编号的 `main` 始终是首选主图。

原始商品图片只作为事实和生成依据，不得被生成资产覆盖。生成结果统一保存到 `output/`。

每个文件名对应的拍摄角度、内容要求、用途和缺失处理详见 [商品白底图库说明](./products/README.md)。
