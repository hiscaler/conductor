# 商品资料库

本目录使用两个 UTF-8 CSV 文件保存可重复使用的商品事实，便于直接编辑和通过 Git 查看逐行变化。CSV 是唯一事实源。

## 文件结构

```text
data/
├── product-catalog.csv
├── product-attributes.csv
└── products/
    └── {SPU}/
        └── {SKU}/
            ├── main.png
            ├── back.png
            ├── left.png
            ├── right.png
            ├── top.png
            └── detail-01.png
```

## 使用方法

1. 在 `product-catalog.csv` 中增加或维护通用商品记录，每行一个 SKU。
2. 品类专属参数写入 `product-attributes.csv`，每行一个属性。
3. 按 `data/products/{SPU}/{SKU}/` 保存原始商品图片，每个 SKU 至少提供一个无编号的 `main` 主图。
4. 只录入已经确认、可直接使用的商品事实；未知内容留空。
5. Agent 每次读取 CSV 时先执行数据校验，校验通过后再合并主表、扩展属性和图库。

## 商品主表

`product-catalog.csv` 只保存跨品类通用字段，包括：

- SPU、SKU、商品名称、类目和产品类型。
- 单个 SKU 固定包含的商品或配件。
- 通用长宽高、重量、材质、颜色、型号和规格。
- 已确认功能、商品特点、适用对象和护理说明。
- 定制、包装、风险/禁用声明和更新时间。

商品主表不保存认证信息或认证状态。只有确有证据的认证才作为独立扩展属性写入 `product-attributes.csv`，并在那里记录资料来源和核验日期；没有证据时只在主表“风险/禁用声明”中约束不得宣称。

商品主表不保存图片路径，也不要求用户填写“资料来源”定位图片。系统始终根据每行的 `SPU` 和 `SKU` 自动查找 `data/products/{SPU}/{SKU}/main.{png|jpg|jpeg|webp}`。

不得为杯口直径、服装胸围、电子接口等单一品类参数持续增加主表列；这些内容写入扩展属性。

## 扩展属性

`product-attributes.csv` 使用“一行一个属性”的结构：

```text
SKU,属性组,属性名称,属性值,单位,值类型,是否平台必需,适用平台,资料来源,资料更新时间,备注
```

- `SKU` 必须存在于商品主表，不重复保存 SPU。
- `值类型` 允许：`数字`、`文本`、`布尔值`、`列表`。
- `是否平台必需` 允许：`是`、`否`。
- 同一 SKU 可以有任意数量的扩展属性。
- 一个属性适用于多个平台时，每个平台单独增加一行。

示例品类属性包括容量、杯口直径、服装胸围、面料克重、电子接口、兼容系统、承重和展开尺寸。示例只说明结构，不要求主表固定这些字段。

## 自动校验

Agent 每次读取商品资料时必须先校验；开发者也可以在仓库根目录运行：

```bash
npm test
```

校验内容包括：

- 两个 CSV 的文件编码、表头、列数和引号结构正确。
- SPU、SKU、商品名称、产品类目和产品类型不得为空。
- SKU 去除首尾空格并忽略大小写后必须全局唯一。
- 产品类型只允许 `普货`、`定制类`。
- 长度、重量和包装数字字段只能填写大于或等于零的数字，不附加单位。
- 资料更新时间使用 `yyyy-mm-dd`，未知时留空。
- 扩展属性中的 SKU 必须存在于商品主表。
- 扩展属性选择“数字”值类型时，属性值必须是数字。
- 商品主表按 SPU/SKU 推导的图库目录必须存在，且每个 SKU 只能有一个无编号 `main` 主白底图。
- 扩展属性的资料来源为可选事实证据；填写本地文件路径时目标文件必须存在。

发现错误时应返回文件名、行号、字段和值，例如：

```text
data/product-catalog.csv 第 6 行，“长度cm”填写为“10cm”；请只填写数字“10”。
```

校验发生在 Agent 读取或运行 `npm test` 时。不得静默修正可能改变商品事实的错误。

## 匹配优先级

```text
当前对话中用户明确修改
> product-catalog.csv 中的标准化 SKU 精确记录
> CSV 中的 SPU/商品名称唯一匹配记录
> 已确认供应商资料
> 商品图片可见事实
> 同类商品和评论形成的市场建议
```

- SKU 精确匹配优先，匹配时去除首尾空格并忽略英文字母大小写。
- 同一个名称匹配到多个 SKU 时必须让用户选择。
- 不得借用同一 SPU 下其他 SKU 的图片。
- CSV 空值不得由竞品资料自动覆盖。

## SKU 编码

所有 SKU 固定 **9 位**，结构为三段、每段 3 位；某一段信息不足时在**左侧**补 `0`。仅使用大写字母和数字。

```text
CCC + SSS + VVV
品类     规格     变体
```

| 段 | 长度 | 规则 | 示例 |
| --- | --- | --- | --- |
| 品类 | 3 | 品类缩写；不足时左侧补 `0` 至 3 位 | `MUG`、`BOX`、`0TE` |
| 规格 | 3 | 该品类最关键规格数字或代码；不足左侧补 `0` | `011`=11oz、`500`=500ml、`00M`=M 码、`000`=无规格 |
| 变体 | 3 | 颜色/款式代码；不足左侧补 `0`，或用流水号 | `0WH`、`0RD`、`001` |

当前马克杯示例：

```text
MUG0110WH  白色 11oz
MUG0110PK  粉胆粉把 11oz
MUG0110RD  红胆红把 11oz
MUG0110GN  绿胆绿把 11oz
MUG0110BK  黑胆黑把 11oz
```

无关键规格的配件可用规格段 `000`，例如礼盒 `BOX000001`。

## SKU 与组合销售

用户一次输入多个 SKU 时，系统将其作为一个组合 listing，例如：

```text
MUG0110RD * 2, BOX000001 * 1
```

未写数量时默认 1，相同 SKU 自动合并数量。系统在当前任务中识别多件装、混色、混款或套装，并将结果用于标题、包装清单、图片数量、成本和平台属性。组合关系不写入商品主表；只有用户明确要求建立新的套装 SKU 时才新增记录。

## 多值、数字和日期

- 描述型多值字段使用半角竖线 `|` 分隔。
- 长度统一使用 `cm` 数值，重量统一使用 `g` 数值。
- 数字字段只填写数字；未知时留空，不写“待确认”。
- 日期使用 `yyyy-mm-dd`。
- 容量等品类属性写入扩展属性，可分别保存 `oz` 和 `ml` 两行，或保存已确认主单位并在生成时换算。

## 图片命名

- `main`：必需，主白底图。
- `back`、`left`、`right`、`top`：选填角度图。
- `detail-01`、`detail-02`：选填细节图。
- 支持 `png`、`jpg`、`jpeg`、`webp`。
- 同一角色不得同时存在多个扩展名文件。

具体拍摄角度、内容要求和缺失处理见 [商品白底图库说明](./products/README.md)。原始商品图片不得被生成资产覆盖，生成结果统一保存到 `output/`。
