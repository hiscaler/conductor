# 可执行动作菜单

## 使用原则

“下一步执行清单”必须同时包含文字说明和可执行动作。

文字说明用于帮助用户理解为什么要做；动作菜单用于让用户直接选择下一步，例如“生成图片”“保存文案”“做上架检查”。

启动向导不使用本文件的 UI 选择器规则，固定使用 [start-guide](./start-guide.md) 中的纯数字流程菜单。

优先交互方式是弹出选择对话框，而不是要求用户手动输入动作 ID。

用户在对话框中选择动作后，核心 Agent（Conductor Agent / 指挥家）必须根据动作映射调度对应子 Agent，并把结果保存到约定位置。

如果运行环境不支持弹窗或选择器，才退回文本动作 ID 方式。

所有产物必须遵守 [输出目录和文件命名规范](./output-structure.md)，统一保存到：

```text
output/{目标平台}/{产品类目}/{产品名称}/
```

## 动作字段

每个动作必须包含：

- 动作 ID
- 展示序号
- 动作名称
- 说明
- 默认建议
- 是否需要确认
- 触发子 Agent
- 预计产物
- 输出位置

## UI 选择器规则

当最终输出包含可执行动作时，核心 Agent 应优先触发 UI 选择器。

选择器要求：

- 标题：`选择下一步动作`
- 说明：用一句话说明当前推荐动作
- 选项数量：优先展示 2-5 个最相关动作，不要一次展示所有动作
- 推荐项：把默认建议为“建议”的动作排在前面
- 多选：当动作之间没有依赖冲突时允许多选
- 确认：涉及生成图片、写文件、覆盖文件、联网调研、成本测算的动作必须确认
- 兜底：如果用户关闭弹窗，不执行动作，只保留输出结果

每个选项应显示：

- 动作名称
- 一句话说明
- 预计产物
- 输出位置

## 文本兜底规则

当 UI 选择器不可用时，才提示用户输入动作 ID。

文本兜底必须使用纯数字展示序号，不能要求用户输入 `A1`、`A2` 这类带字母编号。

内部可以保留稳定的动作 ID，例如 `save_copy_assets`、`generate_main_image`，但用户看到和输入的应该是：

- `1`
- `2`
- `3`

这样用户只需要输入数字即可。

示例：

```text
请选择下一步动作：
1. 保存文案资产
2. 生成主图
3. 做上架前 QA
```

如果允许多选，使用逗号分隔：

```text
请输入要执行的动作序号，例如：1,2
```

## 核心 Agent 执行规则

- 如果用户只说“继续”，核心 Agent 优先弹出选择器；如果选择器不可用，执行默认建议为“建议”的第一个动作前需要确认。
- 如果用户选择多个动作，核心 Agent 按依赖顺序执行。
- 如果动作依赖缺失信息，先输出阻塞项，不执行。
- 如果动作会生成图片、写文件或覆盖已有文件，必须说明产物路径；不得覆盖已有文件，除非用户明确要求。
- 只有方向、关键词、人群或视频链接时，下一步默认建议必须包含 `discover_trend_video_products`。
- `generate_full_image_set` 必须按套图脚本逐张执行。图片生成工具一次只返回一张图时，必须循环调用直到完整图片清单全部完成；不能只生成主图或单张组合预览图。
- 图片验收报告状态为“未完成”时，下一步默认建议必须包含 `generate_missing_images`。
- 如果动作执行失败，必须返回失败原因、已完成产物和下一步建议。

## 常见依赖

- 生成主图前，需要有套图脚本或产品图片提示词。
- 生成整套图片前，需要确认平台、图片规格和产品外观。
- 生成视频前，需要确认平台、产品品类、视频比例、时长、产品外观和核心卖点。实拍视频或供应商视频不是前置条件；优先根据商品参考图或已生成商品图自动生成，没有图片但产品资料充分时根据产品资料生成。用户未指定场景时，由 `visual-production-agent` 按 `platforms/video-scene-presets.md` 自动选择预设场景。
- 趋势与短视频找品前，需要有方向、关键词、人群或视频链接；必须先识别目标国家/地区、选择数据源并生成本地语言关键词。如需读取外部平台数据，必须说明数据源和访问限制。
- 热销榜与评论研究前，需要目标市场、目标平台或候选平台，以及商品名称/类目/本地语言关键词中的至少一种；必须记录抓取日期、样本数和访问限制。
- 供应链验证前，需要商品名称、产品类目或本地语言关键词中的至少一种。应优先查 1688、Alibaba、义乌购或用户指定平台，默认输出 3-5 家候选供应商；公开联系方式未展示或访问受限时写“未公开”“需登录”或“未获取”，不得编造。平台需要登录时，用户只负责登录和处理验证，Agent 负责搜索、筛选、打开候选页和提取数据。
- 自动参考示例生成前，应先完成商品识别；如需市场化建议，还应先完成可访问范围内的热销榜、竞品评论和未来节日筛选。用户必须复制、修改并回传商品资料本体后才执行原任务；回复“重新生成示例”时触发 `regenerate_product_example`。
- 保存文案资产前，需要有文案资产。
- 上架前 QA 前，需要有文案、图片脚本和合规检查。
- 利润测算前，需要采购价、可追溯的供应链候选公开报价、运费或可用的成本假设；如果已有供应链候选表，必须先判断有效报价数量。只有包含平台、店铺名称、商品/店铺网址、价格区间、MOQ 或起订条件、抓取日期和获取状态的报价，才能用于采购价预估；泛化价格区间不能使用。
