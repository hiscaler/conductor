# 可执行动作菜单

## 使用原则

“下一步执行清单”必须同时包含文字说明和可执行动作。

文字说明用于帮助用户理解为什么要做；动作菜单用于让用户直接选择下一步，例如“生成图片”“保存文案”“做上架检查”。

启动向导不使用本文件的 UI 选择器规则，固定使用 [start-guide](./start-guide.md) 中的纯数字流程菜单。

优先交互方式是弹出选择对话框，而不是要求用户手动输入动作 ID。

用户在对话框中选择动作后，核心 Agent（Conductor Agent / 指挥家）必须根据动作映射调度对应子 Agent，并把结果保存到约定位置。

如果运行环境不支持弹窗或选择器，才退回文本动作 ID 方式。

所有产物必须遵守 [输出目录和文件命名规范](./output-structure.md)，同一轮统一保存到：

```text
output/{平台}-{市场}/{Listing标识}[-vN]/
```

正式执行前先分配 Listing 版本目录；完整 16 章生产报告自动保存为该目录下固定的 `上架/完整生产报告.md`，不需要用户再选择“保存完整报告”。聊天默认只展示本轮相关结果和实际报告路径。

## 动作字段

每个动作必须包含：

- 动作 ID
- 展示序号
- 动作名称
- 说明
- 默认建议
- 是否需要确认
- 触发子 Agent
- 预计产物
- 输出位置

## UI 选择器规则

当最终输出包含可执行动作时，核心 Agent 应优先触发 UI 选择器。

选择器要求：

- 标题：`选择下一步动作`
- 说明：用一句话说明当前推荐动作
- 选项数量：展示 1-5 个当前任务范围内的相关动作；只有 1 个合理动作时只展示 1 个，不得为了凑数量加入扩展任务
- 推荐项：把默认建议为“建议”的动作排在前面
- 多选：当动作之间没有依赖冲突时允许多选
- 确认：用户选择启动菜单或下一步动作即视为同意执行该动作；只有扩大任务范围、覆盖已有文件或产生外部影响时才再次确认
- 兜底：如果用户关闭弹窗，不执行动作，只保留输出结果

每个选项应显示：

- 动作名称
- 一句话说明
- 预计产物
- 输出位置

## 文本兜底规则

当 UI 选择器不可用时，才提示用户输入动作 ID。

文本兜底必须使用纯数字展示序号，不能要求用户输入 `A1`、`A2` 这类带字母编号。

内部可以保留稳定的动作 ID，例如 `save_copy_assets`、`generate_main_image`，但用户看到和输入的应该是：

- `1`
- `2`
- `3`

这样用户只需要输入数字即可。

示例：

```text
请选择下一步动作：
1. 修改本轮文案
2. 重生成指定图片
3. 查看本轮产物
```

如果允许多选，使用逗号分隔：

```text
请输入要执行的动作序号，例如：1,2
```

## 任务范围过滤（强制）

下一步动作必须先按用户最近一次启动菜单或明确请求过滤，再按本轮实际状态排序。动作“可能有帮助”不等于与当前任务相关。

本规则适用于全部启动菜单和自然语言单项任务，菜单 2 只是说明过滤方式的示例，不是唯一受约束的场景。

过滤顺序：

1. 读取本轮启动菜单编号；组合菜单取任务范围并集。
2. 只保留以下三类动作：补齐本轮明确请求但尚未完成的产物、修改/重生成本轮明确请求的产物、查看本轮实际产物。
3. 完整生产报告中写“本轮未执行”或“待确认”的章节，不得自动成为下一步任务范围；缺供应链报价、利润数据、视频、上架包或 QA 结果，不能单独作为推荐理由。
4. 用户没有请求的供应链、利润、合规、测试、竞品、视频、上架包和上架前 QA，不得出现在下一步动作中。
5. 使用稳定动作 ID 执行 `node scripts/next-action-scope.mjs <启动菜单编号> <动作ID...>`；校验失败时必须删除越界动作，不能交付。
6. 最终只展示 1-5 个动作，并重新编号为 `1`、`2`、`3`；不得沿用全局动作表序号。

用户后续明确提出新任务时，才将该请求加入新的任务范围。例如菜单 2 完成后，只有用户主动要求“继续做供应链”时，才允许出现供应链动作。

## 核心 Agent 执行规则

- 如果用户只说“继续”，核心 Agent 优先弹出选择器；如果选择器不可用，展示最相关的数字动作，不得自动扩大任务范围。
- 如果用户选择多个动作，核心 Agent 按依赖顺序执行。
- 生成下一步动作前必须先按“任务范围过滤”执行，并运行 `node scripts/next-action-scope.mjs`；全局动作池中的“建议”标签不能绕过任务范围。
- 如果动作依赖缺失信息，先输出阻塞项，不执行。
- 菜单 11 和 `update_growth_review` 必须先验证实际商品详情链接，并取得复盘时间范围和运营数据；只有商品名称时不得执行、保存报告或分配目录版本。
- 如果动作会生成图片、写文件或覆盖已有文件，必须说明产物路径；不得覆盖已有文件，除非用户明确要求。
- 正式生产批次的第一个写入动作执行前，必须把基础 Listing 目录传给 `node scripts/output-versioning.mjs output/{平台}-{市场}/{Listing标识}`，并记录脚本返回的 Listing 版本目录。同一批次的后续动作全部复用该目录，不得再次分配版本；只有用户重新生成同一 SKU 或开始新批次时才分配下一个目录。目录内文件名不得添加 `-vN`。
- 动作只创建其实际产物所需的父目录；不得因为动作菜单列出了供应链、利润、合规、测试、竞品或视频路径就预创建这些目录。交付前运行 `node scripts/check-output-layout.mjs`，不得留下空目录。
- 只有方向、关键词、人群或视频链接时，下一步默认建议必须包含 `discover_trend_video_products`。
- `generate_full_image_set` 必须按套图脚本逐张执行。图片生成工具一次只返回一张图时，必须循环调用直到完整图片清单全部完成；不能只生成主图或单张组合预览图。
- 图片验收报告状态为“未完成”时，下一步默认建议必须包含 `generate_missing_images`。
- `generate_missing_images` 只处理记录为“暂停/未生成”且目标文件尚不存在的图片。动作执行前必须展示图片序号、暂停原因、最低补充资料、恢复目标 Listing 版本目录和预定文件路径；资料仍缺失时先索取最低必要值，不生成占位图。
- 用户直接回复暂停记录所需资料，等同于选择 `generate_missing_images`，无需再次要求选择动作；系统复用当前商品档案、创意策略和套图脚本。
- 同一未完成批次的断点续做写入原版本目录，不重新分配版本；动作授权包含新增缺失图片以及更新该版本的套图脚本、图片验收报告和完整生产报告，但不包含覆盖任何已存在图片。
- 商品身份、外观、SKU/变体、销售数量或核心组件变化时，不执行断点续做，改为新生产批次；目标图片文件已经存在但不可用时使用 `regenerate_selected_images`，默认创建新版本，除非用户明确授权替换准确路径。
- 如果动作执行失败，必须返回失败原因、已完成产物和下一步建议。

## 常见依赖

- 生成主图前，需要有套图脚本或产品图片提示词。
- 生成整套图片前，需要确认平台、图片规格和产品外观。
- 生成视频前，需要确认平台、产品品类、视频比例、时长、产品外观和核心卖点。实拍视频或供应商视频不是前置条件；优先根据商品参考图或已生成商品图自动生成，没有图片但产品资料充分时根据产品资料生成。用户未指定场景时，由 `visual-production-agent` 按 `platforms/video-scene-presets.md` 自动选择预设场景。
- 趋势与短视频找品前，需要有方向、关键词、人群或视频链接；必须先识别目标国家/地区、选择数据源并生成本地语言关键词。如需读取外部平台数据，必须说明数据源和访问限制。
- 热销榜与评论研究前，需要目标市场、目标平台或候选平台，以及商品名称/类目/本地语言关键词中的至少一种；必须记录抓取日期、样本数和访问限制。
- 供应链验证前，需要商品名称、产品类目或本地语言关键词中的至少一种。应优先查 1688、Alibaba、义乌购或用户指定平台，默认输出 3-5 家候选供应商；公开联系方式未展示或访问受限时写“未公开”“需登录”或“未获取”，不得编造。平台需要登录时，用户只负责登录和处理验证，Agent 负责搜索、筛选、打开候选页和提取数据。
- 自动参考示例生成前，应先完成商品识别；如需市场化建议，还应先完成可访问范围内的热销榜、竞品评论和未来节日筛选。用户必须复制、修改并回传商品资料本体后才执行原任务；回复“重新生成示例”时触发 `regenerate_product_example`。
- 保存文案资产前，需要有文案资产。
- 上架前 QA 前，需要有文案、图片脚本和合规检查。
- 利润测算前，需要采购价、可追溯的供应链候选公开报价、运费或可用的成本假设；如果已有供应链候选表，必须先判断有效报价数量。只有包含平台、店铺名称、商品/店铺网址、价格区间、MOQ 或起订条件、抓取日期和获取状态的报价，才能用于采购价预估；泛化价格区间不能使用。
