# 输出目录和文件命名规范

## 使用原则

输出目录只使用两个定位层级：平台市场和 Listing 版本目录。商品名称、类目、SPU、包含内容等可变信息写入商品资料，不再作为目录层级，避免同一商品因为改名或类目调整产生多个目录。

固定结构：

```text
output/{平台}-{市场}/{Listing标识}[-vN]/
```

示例：

```text
output/Temu-US/MUG0110RD/
output/Temu-US/MUG0110RD-v2/
```

平台和市场由系统根据当前任务自动生成，不要求用户额外填写目录名称。

## 平台市场标识

- 格式为 `{平台展示名}-{市场代码}`，例如 `Temu-US`、`Amazon-JP`、`Etsy-GB`。
- 平台使用统一展示名，例如 `Temu`、`Amazon`、`TikTok-Shop`。
- 市场已确定时优先使用常用两位国家或地区代码，例如美国 `US`、日本 `JP`、英国 `GB`、德国 `DE`。
- 平台或市场暂未确定时使用 `待定`，例如 `待定-US`、`Temu-待定`；信息确认后，新产物进入正式目录，不把待定目录当作正式交付目录。
- 同一商品面向不同平台或市场时必须分开保存，不能混用文案、平台属性、图片规格或视频规格。

## Listing 标识

Listing 标识由系统自动生成，不要求用户手工命名。

生成优先级：

1. 单个已匹配 SKU 且销售数量为 1：使用商品主表中的标准 SKU，例如 `MUG0110RD`。
2. 销售数量大于 1 或包含多个 SKU：按标准 SKU 排序并合并重复数量，生成 `组合-{SKU}x{数量}+{SKU}x{数量}`。
3. 没有 SKU 的具体商品：使用 `未建档-{简短商品名}`。
4. 尚无具体商品的找品任务：使用 `找品-{简短方向}`。
5. 只有竞品、关键词或榜单的调研任务：使用 `调研-{简短关键词}`。

示例：

```text
output/Temu-US/MUG0110RD/
output/Temu-US/组合-MUG0110WHx6/
output/Temu-US/组合-BOX000001x1+MUG0110RDx2/
output/Temu-US/未建档-红色定制马克杯/
output/待定-US/找品-宠物出行用品/
```

规则：

- SKU 匹配沿用商品资料库规则：去除首尾空格、忽略英文字母大小写，命中后使用主表标准写法。
- 组合标识必须与本轮实际售卖内容一致；即使只有一个 SKU，销售数量大于 1 时也必须写入数量。数量变化视为不同 Listing。
- 标识中的文件系统非法字符替换为短横线；连续空格压缩为一个短横线。
- 商品改名、标题优化或类目调整不得改变已确定的 SKU 或组合 Listing 目录。
- 目录末尾由版本分配器添加的 `-v2`、`-v3` 只表示生产批次，不属于 SKU、组合标识或商品事实。

## Listing 目录

同一个 Listing 的同一轮产物放在一个独立版本目录。首次生产使用基础目录，后续生产使用带版本后缀的同级目录：

```text
output/{平台}-{市场}/{Listing标识}/
output/{平台}-{市场}/{Listing标识}-v2/
```

每个版本目录内部使用稳定的候选结构和文件名；下列子目录仅在本轮实际产生对应文件时创建：

```text
output/{平台}-{市场}/{Listing版本目录}/
  商品资料.md
  文案/
  图片/
  视频/
  竞品/
  供应链/
  上架/
    完整生产报告.md
  合规/
  利润/
  测试/
```

`商品资料.md` 至少记录商品名称、标准类目、SPU、标准 SKU 或 SKU 组合、销售数量、目标平台、目标市场、当前确认事实和当前生产版本。目录定位依赖 Listing 标识及生产版本，不依赖商品名称。

### 按需创建目录

- 只创建本轮实际需要写入文件的目录；创建文件时可以同时创建其直接父目录。
- 未执行供应链、利润、合规、测试、竞品、图片或视频任务时，不得预创建对应目录。
- 完整生产报告必须保留 16 章，但“本轮未执行”只记录在报告正文中，不对应空目录或空占位文件。
- 不得为了展示完整目录树而一次性创建所有候选子目录。
- 正式生产结束前运行 `node scripts/check-output-layout.mjs`；检查失败时必须移除空目录，再重新检查。

## 文件命名

面向用户查看的文件和卖家侧栏目使用中文。只有可直接复制到目标平台、面向买家或用于搜索及广告投放的最终文案值使用目标市场语言。

推荐命名：

```text
商品资料.md
文案/文案资产.md
文案/关键词清单.md
图片/01-主图.png
图片/02-到手内容图.png
图片/03-规格图.png
图片/图片验收报告.md
图片/套图脚本.md
视频/01-主视频.mp4
视频/视频脚本.md
视频/视频验收报告.md
竞品/竞品分析.md
供应链/供应商候选表.md
供应链/供应链风险报告.md
上架/上架包.md
上架/上架前QA报告.md
上架/完整生产报告.md
合规/合规风险报告.md
利润/利润测算.md
测试/测试计划.md
```

具体图片数量和图型由平台、品类和产品类型规则决定，不在目录规范中固定。

`上架/完整生产报告.md` 是每个 Listing 版本目录中的固定报告文件名。正式执行产生选品、竞品、供应链、文案、图片、视频、合规、利润或 QA 结果时，必须在本轮独立版本目录中同步生成 16 章报告。禁止创建 `完整生产报告-v2.md`、`文案资产-v2.md` 或 `01-主图-v2.png` 这类文件级版本。

## 版本和覆盖

- 基础 Listing 目录不存在时，首次生产使用 `output/{平台}-{市场}/{Listing标识}/`。
- 基础目录或历史版本目录存在时，新一轮生产创建同级的 `{Listing标识}-v2/`、`-v3/` 等目录，不得静默覆盖。
- 同一次生产中的商品资料、文案、图片、视频、验收报告和完整生产报告必须全部进入同一个 Listing 版本目录。
- 每个版本目录内部继续使用固定文件名，不得给单个文件添加 `-vN`。
- 历史版本目录不自动删除；需要整理错误的文件级版本时，必须先建立文件与目标版本目录的映射，确认无冲突后再迁移。

### 强制版本预检

每个正式生产批次在首次写入 `output/` 前，只调用一次版本分配器，并传入不带版本后缀的基础 Listing 目录：

```text
node scripts/output-versioning.mjs output/Temu-US/MUG0110RD
```

必须使用脚本返回的 Listing 版本目录完成本轮全部写入：

- 基础 Listing 目录及历史版本目录均不存在时，本轮为 `v1`，脚本返回基础目录。
- 任一 Listing 版本目录存在时，以现有最大目录版本为基准，返回下一个 `{Listing标识}-vN/`。
- 同一生产批次的后续动作必须复用第一次返回的目录，不得为补图、视频、QA 或保存文件再次分配版本；用户重新生成同一 SKU 或明确开始新一轮生产时，才调用脚本分配下一个目录版本。
- 图片因资料不足暂停且当前批次状态为“未完成”时，用户补齐暂停记录中的最低资料属于同一批次断点续做。只要预定图片文件尚不存在，就继续写入原 Listing 版本目录，不调用版本分配器；允许同步更新该版本的套图脚本、图片验收报告和完整生产报告。
- 断点续做前必须从暂停记录确定准确的恢复目标 Listing 版本目录和预定文件路径，不得仅凭“最新目录”猜测。无法唯一确定时先让用户确认目标批次。
- 商品身份、外观、SKU/变体、销售数量或核心组件发生变化时，不再视为原批次补图，必须调用版本分配器创建新版本并重新检查受影响资产。预定图片文件已经存在但不可用时属于重生成，默认创建新版本；只有用户明确授权替换准确路径时才可覆盖。
- 版本号只添加到 Listing 目录；目录内的文案、图片、视频、提示词、字幕、音频、验收报告、上架包和完整生产报告文件名均不得添加版本后缀。
- 不得把已带 `-vN` 的目录作为脚本输入；输入始终是不带版本后缀的基础 Listing 目录。
- 只有用户明确要求替换准确版本目录中的文件时才允许覆盖；写入前必须列出替换路径。
- 聊天结果和完整生产报告必须记录脚本返回的实际 Listing 版本目录及实际保存路径。

## 动作输出路径

所有下一步动作必须遵守本规范，例如：

```text
output/Temu-US/{Listing版本目录}/文案/文案资产.md
output/Temu-US/{Listing版本目录}/图片/01-主图.png
output/Temu-US/{Listing版本目录}/图片/图片验收报告.md
```
